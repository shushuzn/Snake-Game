# Snake-Game 首轮 Playtest 方案（Round 1）

> 版本：v1（2026-08-07）
> 作者：quality-lead（严守真）
> 目的：验证 **game.js 架构改革（v1.44~v1.55，11 个周边域迁入独立模块，闭包共享状态 90→61）之后核心玩法循环依然好玩**，并采集体验基线数据。
> 前置状态：自动化测试 16 spec / 36 项全绿（Chromium）；本方案补齐自动化覆盖不到的**主观体验层**。
> 性质：**建议性门控（advisory）**——本方案给出通过判定，最终放行由用户决定。

---

## 0. 背景与定位

架构改革的核心承诺是"功能零回归 + 可维护性提升"。现有 36 项 E2E 已证明**功能层零回归**（核心循环、贪吃、持久化、签到、音量、暂停、特殊模式、结算卡片）。但"好玩"是主观体验，无法被断言覆盖，且改革后从未做过系统化 Playtest。

本轮 Playtest 不做"找 bug"为主（那是回归套件的活），而是：

1. **主观面验证零回归**：改革后核心循环的乐趣/心流是否保持。
2. **采集体验基线**：心流、乐趣、道具感知、难度感知、重开意愿，形成可对比的基线数据集。
3. **暴露自动化测不到的问题**：引导完成率、卡点、挫败瞬间、各模式乐趣差异。

设计哲学锚点：**MDA 框架**（机制→动态→美学）、**自我决定论**（自主/胜任/关联）、**心流平衡**、**Bartle 玩家类型**。

## 1. Playtest 目标与假设

### 1.1 目标

| 编号 | 目标 | 关联 MDA 层 | 验证方式 |
|------|------|-------------|----------|
| G1 | 验证改革后核心循环"依然好玩"（主观零回归） | 动态→美学 | 心流自评 + 乐趣分 + 重开率 |
| G2 | 采集体验基线数据，供后续版本对比 | 全层 | 遥测 + 问卷 |
| G3 | 识别道具/连击系统的胜任感与心流贡献 | 机制→美学 | 道具使用×心流交叉分析 |
| G4 | 识别各模式乐趣差异与难度曲线问题 | 机制→动态 | 分模式乐趣分 + 观察 |
| G5 | 评估新手引导完成率与首局留存关系 | 美学→自我决定论(胜任) | 引导进度 + 首局行为 |

### 1.2 可验证假设（H1~H5）

> 每一条都给出：假设、所需数据、判定方式。统计上定位为**探索性基线**（n≈10，不做显著性硬结论，用描述统计 + 效应量提示）。

**H1（道具 → 胜任感）**：道具系统提升玩家胜任感。
- 依据：MDA 中道具是机制，效果是"掌控局面"的美学反馈；自我决定论中胜任感来自可感知的成长。
- 数据：道具使用次数、心流自评、"我能掌控局面"单题自评、乐趣分。
- 判定：使用过道具的被试，其心流自评均值 ≥ 未使用道具被试均值 +1；且"道具使用次数"与"掌控感自评"呈正相关（r ≥ 0.3 即提示）。

**H2（连击 → 心流）**：连击系统制造心流。
- 依据：心流=挑战与技能匹配+即时反馈；连击是即时反馈的强度放大器。
- 数据：单局最高连击、心流自评、断连事件（红色闪烁反馈）记录。
- 判定：触发连击 ≥3 的局，心流自评 ≥5 的比例 ≥ 未触发连击局的 1.5 倍；断连后 15s 内主动重开的比例 ≥ 40%（受挫→立即再来一局 = 心流被破坏但动机保留）。

**H3（引导 → 首局留存）**：完成新手引导分层（至少第一层）的玩家首局留存更好。
- 依据：自我决定论中，胜任感不足是早期流失主因；分层引导降低认知负荷。
- 数据：引导完成率、首局时长、首局后重开率。
- 判定：完成引导的被试首局时长均值 ≥ 未完成者 +30%；首局后重开率 ≥ 未完成者。

**H4（模式 ↔ Bartle 类型）**：不同玩家类型对模式乐趣偏好有差异。
- 依据：Bartle 四型——成就者追求分数/进度，探索者追求发现/成长，社交者追求关联/对抗，杀手追求竞争/击败。
- 数据：Bartle 分类前测 + 分模式乐趣分。
- 判定：成就者给经典/限时的乐趣分均值最高；探索者给肉鸽/无尽最高；社交者给多人/AI 对战最高；杀手给冲刺/竞技类最高（Top1 命中 ≥3/4 类型即支持）。

**H5（难度曲线 → 心流平衡）**：开局 1 分钟内无"空转式"挫折（长时间无奖励/无进展）。
- 依据：心流平衡要求开局挑战略低于技能并快速给反馈。
- 数据：遥测"首个食物/首个道具被吃时间"、观察"前 60s 卡顿/无进展"记录。
- 判定：首个食物中位时间 ≤ 15s；首个道具中位时间 ≤ 60s；前 60s 无进展卡顿记录 ≤ 2 次/全部 session。

## 2. 测试对象 / 样本设计

### 2.1 规模与结构

- **总量**：8~12 人（建议 10 人）。探索性样本，够做描述统计与分层对比，不追求统计功效。
- **Bartle 分层**（前测问卷分类，非自报）：

| Bartle 类型 | 目标人数 | 招募侧重 |
|-------------|---------|---------|
| 成就者（Achiever） | 2~3 | 分数导向、追求全成就的玩家 |
| 探索者（Explorer） | 2~3 | 喜欢摸清机制、收集图鉴的玩家 |
| 社交者（Socializer） | 2~3 | 喜欢对战/多人/观战的玩家 |
| 杀手（Killer） | 2~3 | 喜欢竞争、挑战高难度的玩家 |

- **经验分层**（同一被试同时打 Bartle 标签与经验标签）：

| 经验层级 | 目标人数 | 说明 |
|----------|---------|------|
| 新手（New） | ≥ 3 | 从未玩过本作、少玩贪吃蛇类——**验证引导与上手** |
| 轻量（Light） | ~4 | 偶尔玩休闲游戏 |
| 资深（Heavy） | ~3 | 深度游戏玩家——**验证深度乐趣与难度** |

- **招募来源**：内部工作室成员（≤50%）+ 外部朋友/社区（≥50%），避免纯内部样本偏差。**禁止招募本作开发者/测试者本人**（他们无法代表新玩家体验）。

### 2.2 排除标准

- 参与过本作架构改革、写过多行本作代码者 → 排除（或仅作专家访谈，不并入数据）。
- 视障/色盲未适配者（本项目有高对比模式，如招募到色盲被试，记录为协变量并观察高对比开关使用）。

### 2.3 环境

- 统一桌面 Chrome（最新稳定版）、统一分辨率 ≥ 1280×800、键鼠。
- 使用本地静态服务器（`python3 -m http.server 4173` 或 `pnpm dev`），**不配置在线后端**（纯前端零依赖承诺场景，离线回退路径即生产路径）。
- 每个 session 前清理 `localStorage`（确保全新玩家状态、引导从第一层开始）。

## 3. 测试方法：三合一

### 3.1 方法总览

| 层 | 工具 | 产出 | 覆盖假设 |
|----|------|------|----------|
| ① 结构化观察 | 观察员清单（表 E） | 行为/情绪/卡点记录 | H2/H3/H5 |
| ② 问卷 | 定量问卷 + 简短访谈 | 心流/乐趣/道具感知/重玩意愿 | H1~H4 |
| ③ 遥测 | 最小遥测埋点（事件序列） | 客观行为数据 | H1~H5 |

### 3.2 结构化观察清单（观察员用，表 E）

> 观察员坐在被试侧后方，**只记录、不提示、不解答**（除非出现卡死等需中断情形）。每条记录格式：`时间戳 + 代码 + 备注`。

| 代码 | 观察项 | 记录要点 |
|------|--------|----------|
| O1 | 首次上手 | 加载→第一次按方向键的秒数；是否犹豫 |
| O2 | 引导交互 | 引导弹出时是否跟随；是否主动打开帮助(H)；卡在引导哪一层 |
| O3 | 首次死亡反应 | 立即重开 / 停留>10s 看结算 / 叹气 / 骂 / 退出 |
| O4 | 道具发现 | 第几个道具被吃；是否主动奔道具；是否困惑道具效果 |
| O5 | 连击反馈 | 断连红色闪烁时反应（皱眉/无感/重开） |
| O6 | UI 卡点 | 找不到按钮/不懂某面板/多次点错 |
| O7 | 模式切换 | 切换流畅度；切模式后是否知道怎么开始 |
| O8 | 情绪标记 | J=joy / C=confusion / F=frustration / N=neutral，带时间戳 |
| O9 | 挫败/放弃 | 是否在局中放弃操作（不动了）；放弃前最后的动作 |

### 3.3 问卷设计

**定量部分（session 末填写，约 5 分钟）**：

A. 心流自评（简化 FSS，5 题，1=完全不同意 ~ 7=完全同意）：
1. 我完全投入到游戏中，忘了时间。
2. 操作很流畅，我知道下一步该做什么。
3. 游戏的挑战难度和我的水平刚好匹配。
4. 我能清晰感到自己越玩越好（胜任感）。
5. 我感到"再来一局"的强烈冲动。

B. 分模式乐趣分（1~7）+ 难度感知（1=太简单 ~ 5=太难，3=合适）+ 是否愿意再玩（是/否）：
- 模式清单：经典 / 限时60s / 冲刺45s / 无尽 / 肉鸽 / AI对战 / 多人 / 观战

C. 道具感知（对已见过的道具逐项）：
- 见过？使用过？感知强度 1~5？出现频率（太少/合适/太多）？

D. 重玩意愿（1~7）+ NPS 式推荐意愿（0~10）。

E. 开放问题（3~5 题）：
1. 最喜欢的一个模式/系统？为什么？
2. 最不喜欢/最困惑的一点？
3. 有没有哪一刻"不想玩了"？发生了什么？
4. 如果只能改一个东西，你改什么？

### 3.4 遥测设计（需 engineering-lead 配合，见 §8.3）

最小事件序列（内存 buffer，`window.__SNAKE_TELEMETRY__`，session 结束导出；**零生产影响、零网络请求**）：

```
session_start          { ts }
game_start             { ts, mode }
game_end               { ts, mode, reason: death|restart|timeout|quit, score, maxCombo, foodsEaten, durationMs }
food_eaten             { ts, itemType }        // 含 10 种道具类型
combo_break            { ts, combo }
guide_progress         { ts, phase, pct }
mode_switch            { ts, from, to }
```

采集口径统一见 §4。

## 5. 测试脚本（每 session 标准化流程，约 50 分钟）

> 观察员与主持人都必须按本脚本执行，控制引导偏差。时间可 ±10%，但**阶段顺序不变**。

### Phase 0 准备（5 min）
1. 主持人说明：这是产品体验测试，不是考试；请按平时习惯玩，可以出声。
2. 签署知情同意（匿名数据处理）。
3. 填 Bartle 分类前测（3~5 题简版）+ 经验自评。
4. 主持人清理 localStorage → 刷新页面 → 确认全新玩家状态。

### Phase 1 上手（8 min）
5. **零指导**：只说"这是贪吃蛇游戏，请开始"。不解释模式/道具/引导。
6. 观察员记录 O1/O2：首次移动时间、引导交互、帮助打开。
7. 让玩家自然玩到第一次死亡或满 8 分钟。

### Phase 2 自由玩（15 min）
8. 玩家自由选择模式与节奏，**观察员只记录不干预**。
9. 确保至少完成 3 局（含死亡结算路径）。
10. 若玩家卡住 >2 分钟无操作，主持人记录"放弃点"并轻提示"可以试试其他模式"（记入观察备注，标记为干预）。

### Phase 3 引导试玩各模式（15 min）
11. 主持人按固定顺序引导体验代表模式（每个模式至少 1 局或 2 分钟）：
    经典 → 限时60s → 冲刺45s → 无尽 → 肉鸽 → AI对战（简单）。
    多人（本地 2 人需陪测）与观战：作为演示性体验，主持人陪测或播放 AI 对战，标注"演示"不并入乐趣分统计权重。
12. 每模式体验后即时口头问一句"好玩吗？几分？"（记入表 C 草稿，正式分以问卷为准）。

### Phase 4 问卷 + 访谈（7 min）
13. 填写定量问卷（§3.3 A~D）。
14. 简短访谈（§3.3 E 开放题），主持人速记。

### Phase 5 结束（2 min）
15. 导出遥测 buffer（若有埋点）；致谢；询问是否愿意参加后续轮次。

## 6. 通过标准（advisory）

> 单轮 Playtest 的**质量门判定**（PASS / CONCERNS / FAIL），供主理人与用户决策，不自动放行发布。

### 6.1 硬性门槛（任一不满足 → FAIL）

| # | 标准 | 阈值 |
|---|------|------|
| S1 | P0/P1 级 bug | **0 个** |
| S2 | 心流自评均值（全体） | ≥ 5.0（7 点量表） |
| S3 | 重开率 R1（死亡后主动重开） | ≥ 60% |
| S4 | 新玩家引导完成率（≥3 名新手） | ≥ 70% |

### 6.2 软性观察项（不满足 → CONCERNS，附改进建议）

| # | 标准 | 阈值 |
|---|------|------|
| S5 | 各模式乐趣分 ≥5 的模式数 | ≥ 5/8 |
| S6 | 道具被发现并主动使用 ≥1 次的被试比例 | ≥ 80% |
| S7 | 首个食物中位时间 | ≤ 15s |
| S8 | 首个道具中位时间 | ≤ 60s |
| S9 | 开放题"最困惑点"提及次数 ≤ 3 次的系统数量 | ≥ 1（指无重大困惑系统） |

### 6.3 判定规则

- 全部硬性门槛通过 → **PASS**（核心循环主观零回归成立，可进入下一阶段）。
- 硬性门槛通过、软性项 ≥2 项不满足 → **CONCERNS**（基线可用，但存在明确体验缺口，需给改进建议）。
- 任一硬性门槛不满足 → **FAIL**（须定位原因：是改革回归还是长期存在的设计问题；回归套件+Playtest 交叉验证）。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 样本偏差（内部员工熟悉项目，高估体验） | 心流/乐趣虚高 | 内外混合招募（内部 ≤50%）；按经验分层分析；排除开发者/测试者本人 |
| 引导偏差（观察员语言/表情暗示） | 污染行为数据 | 标准化脚本；观察员培训"三不"（不提示/不解答/不评价）；主持人非开发者 |
| 遥测实现成本/风险（埋点改生产代码） | 改革"零回归"承诺被破坏 | 最小侵入：内存 buffer + `__SNAKE_TEST__` 钩子旁挂 `__SNAKE_TELEMETRY__`，零网络、零持久化，默认关闭；由 engineering-lead 实现并跑全量回归确认 |
| 小样本统计功效不足 | 误判假设支持/拒绝 | 定位为探索性基线：描述统计 + 效应量 + 分类型观察，不做显著性硬结论；结论标注"提示性" |
| 8 模式导致单模式样本太薄 | 乐趣分不可比 | 首轮聚焦 6 个核心模式；多人/观战降级为演示；结论按模式标注样本数 |
| Bartle 分类主观 | 分层无效 | 用标准化前测问卷（非自报），交叉复核观察员判断 |
| 玩家体验"全靠问卷回忆" | 数据失真 | 三合一：问卷+观察+遥测互证；问卷紧接试玩（Phase 3→4 连续） |
| 一次性 session 无法测留存 | 留存类结论缺失 | 本轮不宣称留存结论；S4/重开率仅作留存代理指标；后续可加 24h 回访小样本 |

## 8. 落地建议：自动化可复用 vs 人工

### 8.1 可复用现有 E2E/工具自动采集（建议工程化）

| 指标 | 现有资产 | 落地方式 |
|------|----------|----------|
| 单局时长 / 得分 / 最高连击 / 道具使用 | `tests/greedy_eat.spec.js` + `__SNAKE_TEST__.getState()` | 扩展贪吃 E2E：跑 N 局模拟，输出时长/道具/连击分布 |
| 难度曲线 / 首个道具时间 / 死亡时间分布 | `tools/autotune/simulate.py`（已有模拟器） | 复用模拟器批量跑经典/限时，产出客观曲线，与 Playtest 遥测互证 |
| 引导完成率 | `tests/guide_regression.spec.js`（已有引导回归） | 扩展：驱动完整引导流程，断言各层可达 |
| 模式切换/结算 | `tests/special_modes.spec.js`、`tests/settlement_card.spec.js` | 已覆盖，Playtest 期间作为 smoke 前置 |

### 8.2 必须人工采集（无法自动化）

- 心流自评、乐趣分、道具感知、重玩意愿（问卷）
- 行为观察：困惑、挫败、卡点、情绪（观察员）
- Bartle 分类（前测问卷）
- 开放题定性反馈

### 8.3 需要主理人协调的资源

1. **engineering-lead**：实现最小遥测埋点（§3.4 事件序列，`__SNAKE_TELEMETRY__` 内存 buffer + session 末导出）。要求：零网络请求、零持久化、默认关闭、实现后全量回归绿。若成本高，退路=观察员手工记录表 B（已在方案中兼容）。
2. **design-strategist**：确认科幻前端（v1.36 深空星云/霓虹风格）对新玩家的理解门槛；如需要，提供 Playtest 邀请材料/刺激素材（封面图、说明卡）。
3. **release-ops-lead**：准备 Playtest 专用构建/运行方式（本地静态服务器，不接在线后端）；协调 session 排期（建议 2 天×5 人）。

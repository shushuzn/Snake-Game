# game.js 拆分分析（2026-08-07）

## 现状
- 规模：5400 行，`bootSnakeGame()` 单闭包
- 结构：284 个顶层共享变量 + 158 个顶层函数，全部在同一闭包作用域内交叉引用
- 已抽取：`src/game/config.js`（常量/存储键/验证函数）、`src/game/utils.js`（纯工具函数）

## 依赖分析（脚本：scripts/analyze-shared-state.cjs）
- 279 个顶层变量中：
  - **9 个**被 ≥8 函数共享（running/storage/paused/mode/settingsRuntime/overlay/bestManager/tileCount/roundStartTime）——高度共享核心
  - **39 个**被 3-7 函数共享
  - **231 个（83%）**被 ≤2 函数引用——低共享
- 模式控制器块（AI对战/多人/观战/每日，~530 行）引用 38 个共享变量 + 6 个外部闭包函数

## 拆分障碍（核心结论）
- **ESM import 是只读绑定**：无法跨文件共享可变闭包状态
- 函数直接读写 `running/score/paused` 等变量（非 `state.xxx` 对象属性）
- 158 个函数互相调用，形成稠密依赖网

## 两种路径评估

### 路径 A：状态对象化（彻底拆分）
- 把 284 变量收敛为 `state` 对象，所有函数改 `state.xxx` 访问
- 然后按功能域拆文件（每个 <800 行）
- 改动量：284 变量 × 全部引用点（数百处），2-3 小时
- 风险：高（机械替换易错），需 72 个 E2E 测试兜底
- 收益：game.js 拆为 ~7 个功能文件，可维护性提升

### 路径 B：保持内核闭包（现状，推荐）
- game.js 作为"游戏内核入口"单文件，内部闭包隔离良好
- 已达成现代架构：ESM 模块化 + Vite 构建 + 测试基建
- 收益/风险比更高；后续可增量外移低依赖函数（83% 变量低共享，潜力仍在）

## 结论
推荐路径 B。若未来需要路径 A，建议作为独立专项（2-3 小时），以 72 个 E2E 测试为回归基线，逐步迁移。
